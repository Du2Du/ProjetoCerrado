1. Resumo executivo

O frontend do Projeto Cerrado é uma aplicação web multipágina, construída com HTML, CSS e JavaScript puro. Ela reúne o portal institucional, quatro painéis de dados agropecuários, capacitações, diagnóstico inteligente, biblioteca pública de documentos e uma área administrativa.

Não há compilação ou framework de componentes. Os arquivos são copiados diretamente para uma imagem Nginx e servidos como conteúdo estático. Os painéis usam amCharts; o diagnóstico usa Leaflet, Chart.js, Axios, jsPDF e html2canvas; a responsividade geral é apoiada por Bootstrap 5.

Situação em cinco pontos

  1. A arquitetura é simples de publicar. O frontend é estático, sem etapa de build; o contêiner Nginx apenas copia os arquivos.
  2. Os painéis tratam falhas parciais. Requisições independentes têm limite de 15 segundos e usam Promise.allSettled, preservando os blocos que carregaram com sucesso.
  3. A biblioteca e a administração têm uma camada de serviços mais madura. Há normalização de contratos, erros tipados, cookies de sessão, CSRF em memória, paginação, estados de interface e validação de arquivos.
  4. A interface compartilha identidade e comportamentos. Cabeçalho, rodapé, cores, tipografia, filtros, abas e estados de dados são reutilizados entre as páginas.
  5. A entrega contempla o ciclo completo de documentos. O público pesquisa e baixa materiais; o administrador autentica-se e pode cadastrar, editar e excluir documentos com imagem de capa e PDF.

6. Painéis de dados

Os quatro painéis seguem um padrão comum: carregam recursos independentes, derivam opções de filtro dos dados retornados, atualizam KPIs/gráficos/tabelas e marcam a fonte como SIDRA/IBGE. Falhas viram estados visuais por componente; o botão “Tentar novamente” recarrega a página.

PainelEndpointsTratamento e filtrosDependência
Leiteproducao-uf, regioes, centro-oeste, goias-meso, goias-municipios, ranking-consumoPeríodo, escala, indicador, regiões, UFs, municípios e produtos. 16 áreas gráficas e tabelas relacionadas.Cada conjunto afeta somente seus alvos.
Corterebanho, abatePeríodo, UFs, trimestre e métrica de abate. Omite total anual quando faltam trimestres.3 gráficos; blocos independentes.
Eucaliptoquantidade, ranking, valor, participacaoPeríodo, produtos, localidades e indicador. Atualiza textos e KPIs conforme a série.4 gráficos; arrays históricos embutidos são esvaziados antes da API.
Seringueirapam, censoPeríodo, UFs e produto. Reaproveita a Promise de cada endpoint para evitar chamada duplicada.Falha do Censo afeta apenas estabelecimentos.

Padrão de resiliência

  1. O card entra em loading e recebe aria-busy="true".
  2. Cada chamada usa AbortController com limite de 15 segundos.
  3. Promise.allSettled mantém disponíveis os componentes cujas requisições foram concluídas.
  4. Resposta HTTP inválida, JSON vazio ou transformação incompatível gera estado de erro/vazio.
  5. Erros técnicos são registrados no console; a tela mostra mensagem pública.
Ponto de arquitetura: as URLs dos quatro painéis estão codificadas como https://api.projetocerradoifg.org/webhook/.... Isso acopla o mesmo código a produção e exige CORS. Uma configuração externa por ambiente reduziria esse acoplamento.

8. Diagnóstico inteligente

O diagnóstico permite buscar um endereço ou selecionar um ponto no mapa, informar cultura, estágio produtivo e problema, e enviar os dados para POST /api/recommendations. A resposta alimenta recomendações, clima atual, quatro gráficos horários, solo e vegetação. O relatório pode ser impresso ou convertido em PDF no navegador.

12. Implantação e operação

12.1 Empacotamento

FROM nginx:alpine
COPY . /usr/share/nginx/html
EXPOSE 80

O frontend é publicado diretamente como aplicação estática. A imagem utiliza Nginx Alpine, copia os arquivos para o diretório público e expõe a porta 80.

12.2 Publicação

O GitHub Actions é disparado em push para main, acessa a VPS por SSH, executa git pull, reconstrói os contêineres e sobe o Compose. O Nginx externo encaminha / para o frontend na porta 8080 e /api/ para o backend na porta 8000.

12.3 Recursos operacionais implementados

RecursoFuncionamento
Implantação automáticaPush em main aciona o workflow de deploy na VPS.
Reconstrução dos serviçosO workflow executa docker compose build e docker compose up -d --remove-orphans.
Separação de rotasO Nginx encaminha páginas para o contêiner frontend e /api/ para o backend.
Simulação de falhaOs painéis aceitam ?simularErroApi=1 para exercitar os estados de erro e retentativa.
Reinício independenteO Compose permite reiniciar apenas frontend, backend ou banco.
